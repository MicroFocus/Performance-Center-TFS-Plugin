1 · Overview

PluginsUI is a standalone desktop application that lets you run OpenText Enterprise Performance Engineering tasks directly from your workstation — without needing Azure DevOps or a build agent.

TabWhat it does
CI Test Run Authenticate, reserve a timeslot, start and monitor a performance test run, and download result artifacts.
Workspace Sync Scan a local repository for performance test scripts (.usr, .jmx, .scala, DevWeb) and upload them to a project's test plan on the server.
Download Scripts Download all test scripts from a domain/project on the server and extract them into a local folder, mirroring the server-side folder structure.

All three tasks use the same connection credentials. Switch between tabs at any time — settings are remembered separately per tab.

2 · First Launch

On first launch the application opens with default placeholder values. Start by filling in the Connection section at the top — this is shared by all three tabs.

Node.js 20 or later must be installed on your machine. Without it the tasks cannot run. Download from https://nodejs.org.

3 · Connection & Authentication

The Connection section is at the top of the window and is shared by all tabs.

Server URL

Enter the full URL of your Enterprise Performance Engineering server:

https://epe.mycompany.com:444
https://epe.mycompany.com:444/?tenant=fa128c06-5436-413d-9cfa-9f04bb738df3

Include the /?tenant=<guid> suffix if your server uses multi-tenancy.

Username / Password authentication

Enter your LRE username and password. Use the Show / Hide toggle next to the password field to reveal what you typed.

Token authentication (SSO servers)

If your server is configured with Single Sign-On (SSO), username/password login is disabled. You must use an API token instead:

  1. Check Authenticate with token.
  2. Enter your Client Id key in the User name / Id key field.
  3. Enter your Client Secret key in the Password / Secret key field.
Token keys look like I_KEY_… (Id) and S_KEY_… (Secret). Obtain them from your LRE administrator.

Domain & Project

FieldDescription
DomainThe LRE domain that contains your project (e.g. DEFAULT).
ProjectThe name of the LRE project you want to work with.

Test Connection

Click Test Connection to verify your server URL and credentials before running a full task. A dialog reports success or failure with a clear error message.

4 · Proxy Settings

If your network requires a proxy to reach the LRE server, expand the Proxy (optional) section and fill in:

FieldExample
Proxy URLhttp://proxy.mycompany.com:8080
Proxy user namedomain\username (leave blank if not needed)
Proxy passwordLeave blank if the proxy is unauthenticated.

Leave the Proxy URL empty if you connect directly to the server.

5 · CI Test Run tab

Use this tab to start and monitor a performance test run on the LRE server.

Test section

FieldDescription
Test ID or YAML Enter a numeric Test ID (visible in LRE under Test Management → Test Plan) or browse to a .yaml / .yml test-definition file. Use Browse… to pick a YAML file.
Workspace dir Root folder of your local repository. Used to resolve relative YAML paths. Leave empty when using an absolute YAML path or a plain numeric Test ID.
Test Instance ID Automatically select… — the task reuses an existing test instance or creates one if none exists (recommended).
Manual selection — pin to a specific Test Instance ID from LRE → Test Lab.

Run Options section

FieldDescription
Post run actionCollate Results, Collate and Analyze (default), or Do Not Collate.
TrendingDo not trend / use associated trend report / specify a trend report ID.
Timeslot durationMinutes to reserve (minimum 30). The test is stopped if the timeslot expires.
Use VUDsCheck to consume Virtual User Day licenses instead of hourly ones.
Status per SLAWhen checked, the run is marked failed if the configured SLA is not met.
On timeslot creation failureRetry with a delay and number of attempts, or do not retry.

Advanced section

FieldDescription
Artifacts directoryWhere result files (reports, logs) are saved. Leave blank for a timestamped folder in %TEMP%.
Node dist pathPath to the task bootstrap file. Leave blank — the application finds it automatically. Use Detect or Browse… only if auto-detection fails.
DescriptionOptional free-text label shown in the output panel header.

6 · Workspace Sync tab

Scans a local directory for performance test script folders and uploads them to the LRE server's test plan, preserving the folder hierarchy.

A folder is recognized as a script if it contains a .usr, .jmx, .scala, or .java file, or both main.js and rts.yml (DevWeb scripts).

Workspace section

FieldDescription
Workspace directoryRoot of the local folder tree to scan. Use Browse… to pick a folder.
Runtime onlyUpload only scripts that have a runtime component (DevWeb / JMeter / Gatling). Leave unchecked to upload all detected types including .usr.
Parallel uploadsNumber of scripts to upload at the same time (1–20). Default: 1. Increase for large repositories if the server supports concurrent uploads.
Success threshold (%)Minimum percentage of scripts that must upload successfully for the task to pass. Leave empty for the default (50%). Set to 100 to fail if even one script fails.
Base commit SHAOptional. Git commit SHA to use for differential sync — only scripts changed since this commit are uploaded. Leave empty for a full sync (all scripts).

Advanced section

FieldDescription
Artifacts directoryWhere upload logs are saved. Leave blank for a timestamped folder in %TEMP%.
Node dist pathLeave blank — auto-detected. Use Detect or Browse… only if needed.
DescriptionOptional label shown in the output panel header.

7 · Download Scripts tab

Downloads all test scripts from the selected domain/project and extracts each one into a local folder that mirrors the server-side test-plan structure.

How the local folder structure is created

Each script on the server has a path like Subject\folder1\SubFolder1 and a name like MyScript. The root Subject segment is stripped and the script is extracted into:

{Download directory}\folder1\SubFolder1\MyScript\
    ├── MyScript.usr
    └── ...

The intermediate .usz archive file (a standard zip) is deleted automatically after extraction — it never appears in the workspace.

Download section

FieldDescription
Download directoryLocal root folder where scripts are extracted. Use Browse… to pick a folder. The folder is created automatically if it does not exist.
Parallel downloadsNumber of scripts to download simultaneously (1–20). Default: 1. Increase to speed up large projects.
Success threshold (%)Minimum percentage of scripts that must download successfully for the task to pass. Leave empty for the default (50%).

Advanced section

FieldDescription
Artifacts directoryWhere download logs are saved. Leave blank for a timestamped folder in %TEMP%.
Node dist pathLeave blank — auto-detected. Use Detect or Browse… only if needed.
DescriptionOptional label shown in the output panel header.

8 · Button Bar

ButtonAction
Load ConfigLoad a previously saved configuration file (.json) for the active tab. Passwords are never stored in the file and must be re-entered.
Save ConfigSave the current form values to a .json file. Passwords are intentionally excluded.
Test ConnectionVerify that the server URL and credentials are correct without starting a full task.
▶ RunStart the task configured in the active tab.
■ StopCancel the running task immediately (kills the entire Node.js process tree).
❓ HelpOpen this user guide in your default browser.
CloseClose the application. If a task is running you will be asked to confirm.
The ▶ Run button and the tab selector are disabled while a task is running to prevent conflicting operations.

9 · Output Panel

The dark panel at the bottom of the window streams live output from the running task. Lines are colour-coded:

ColourMeaning
Light greyNormal information messages.
Red[ERR] — error messages.
Gold[WARN] — warnings.
GreenSuccess or completion messages.

Click Clear (next to "Output") to clear the panel at any time.

Log files are saved to the Artifacts directory so you can review them after the application is closed:

10 · Saving & Loading Configuration

You can save the settings of the active tab to a .json file and reload them later — useful when working with multiple projects or switching between environments.

  • Save Config — prompts you to choose a file location and name.
  • Load Config — picks up all fields from the file. Re-enter passwords after loading.
Passwords are never written to configuration files. You must always re-enter them after loading a saved configuration.

11 · Auto Session Restore

When you close the application, all form values (except passwords) are saved automatically. On the next launch, each tab is restored to its last state — so you only need to re-enter passwords.

The session files are stored here (not normally needed directly):

%LOCALAPPDATA%\PluginsUI\last-session.json ← CI Test Run
%LOCALAPPDATA%\PluginsUI\last-session-sync.json ← Workspace Sync
%LOCALAPPDATA%\PluginsUI\last-session-download.json ← Download Scripts
To reset all settings to defaults, delete the three files above and restart the application.

12 · Command-Line Usage (no GUI)

Companion PowerShell scripts are included alongside PluginsUI.exe. They perform the same tasks without opening the GUI — useful for scripted or automated workflows.

CI Test Run

.\Scripts\run-lre-task.ps1 `
    -PCServer  "https://epe.mycompany.com:444/?tenant=<guid>" `
    -Domain    "DEFAULT"  -Project "MyProject" `
    -TestID    "42" `
    -UserName  "admin"    -Password "s3cr3t"

Workspace Sync

.\Scripts\run-workspace-sync.ps1 `
    -PCServer      "https://epe.mycompany.com:444" `
    -Domain        "DEFAULT"  -Project "MyProject" `
    -WorkspaceDir  "C:\repos\myproject" `
    -UserName      "admin"    -Password "s3cr3t"

Download Scripts

.\Scripts\run-download-scripts.ps1 `
    -PCServer      "https://epe.mycompany.com:444/?tenant=<guid>" `
    -Domain        "DEFAULT"  -Project "MyProject" `
    -WorkspaceDir  "C:\downloads\scripts" `
    -UserName      "admin"    -Password "s3cr3t" `
    -ParallelDownloads 5

Run Get-Help .\Scripts\run-download-scripts.ps1 -Full (or the equivalent for any script) for a complete parameter reference.
